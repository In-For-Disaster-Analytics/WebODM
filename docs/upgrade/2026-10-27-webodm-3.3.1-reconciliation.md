## Remaining validation

The clean app image now builds successfully as `webodm-upgrade-3.3.1:local` (image ID `sha256:20bfd0e6c8174b46c45826e26b4a39c4a7f1db40d0b7cd6045f8cb3496176695`). The final image passes `pip check`, 35 focused backend tests, 56 frontend suites/71 tests, model checks, mocked URL checks and migration model-state consistency. Frontend tests mount only the existing generated UI fixtures read-only; dependencies come from the newly built image. FFmpeg7.0.2 and Splat-Tools1.0.3 execute; Entwine reports2.2.0 through its help output.

A build-tool incompatibility was found by `pip check`: wheel0.48 requires packaging>=24, while WebODM uses packaging16.8. Pinning wheel0.43.0 in the existing Dockerfile build step resolves it; the image was rebuilt and dependency/runtime checks repeated successfully.

The full database-backed Django suite, restored-copy migration validation and connected service/browser acceptance remain pending. The 35 focused tests run without a database or network. No full backend acceptance is claimed.

No `migrate`, database creation/data mutation, live OAuth flow, Tapis job, CKAN publication, Label Studio write, or production service action ran. New `0055_grid_shift_correction` can download grids and alter saved extents; `0056_update_plugins` can download/install plugins. Ten legacy plugin bundles are retained so those existing enabled plugins do not require migration-time downloads, but this is not proof all migration side effects are absent. Both migrations need explicit runtime review before execution.

A deployment still requires database/media backups, restored-copy migration validation, connected feature checks, verified infrastructure documentation and explicit rollout approval. Current auth signature-validation limitations and partial features remain documented; this integration does not claim to fix or complete them.
